# CP25: Structured extraction schema + trusted source-window boundary

CP25 is Phase 1's extraction boundary: the schemas an upstream model (CP26)
will fill, and the **machine-enforced boundary** between a model-suggested
candidate and a persistable requirement. No LLM is called here (CP26), and
no tables are created (CP30 persists `Requirement`).

## Why
Per AGENTS.md: never fabricate a citation/page/requirement, keep every
requirement linked to trusted source metadata, and never persist free-form
model prose as a valid requirement. CP25 makes that enforceable in code
before any model output touches storage.

## What changed
New package `tender_compliance_api/extraction/`:
- `RequirementCandidate` — model output. **No trusted-location fields**
  (`page_number`, `document_version_id`, `bbox`, `source_text` are absent and
  `extra="forbid"`), so a model cannot attach or relocate a page. Required:
  `normalized_text`, `raw_source` (non-blank), `requirement_type`,
  `uncertainty` (tri-state); optional observed `clause_section`/`group_hint`.
- `TrustedSourceContext` — service-owned source window:
  `organization_id/document_id/document_version_id/page_number/clause_number/
  char_start/char_end/bbox/ocr_confidence/location_type/source_text`. Built via
  `from_page(DocumentPage, …)` (page_number/ocr_confidence/cleaned_text from
  the parsed page; source_text defaults to `cleaned_text`).
- `SourcedRequirementCandidate` — the boundary object (candidate + source):
  - `validate_source()` raises `CandidateValidationError` when
    `raw_source` (whitespace-normalized) is not a substring of the trusted
    `source_text`, or `source_text` is missing. This is the literal CP25
    guarantee: **a model cannot move a candidate to a different page/document.**
  - `is_persistable()` → `True` only for `CONFIRMED` candidates that pass
    `validate_source()`; `UNCERTAIN` → human review (CP35); `ABSTAIN` →
    discarded (CP28).
- Enums: `RequirementType` (obligation/prohibition/permission),
  `UncertaintyLevel` (confirmed/uncertain/abstain), `LocationType`
  (exact/approximate); `CandidateValidationError`.

## Scope (included)
Schema + boundary + `from_page` builder + 20 schema/boundary tests
(`tests/test_extraction.py`). Boundary: construction rejects malformed enums
and unknown/extra fields; citation check is the explicit `validate_source()`
gate (avoids pydantic wrapping the typed error) plus `is_persistable()`.

## Scope (excluded — deferred by checkpoint sequence)
- No `Requirement` table / persistence (CP30).
- No LLM adapter to produce candidates (CP26).
- No multi-page windows / fuzzy citation matching (CP27/CP31).
- No chunking or clause hierarchy (CP27).

## Risks / limitations
- `validate_source()` uses whitespace-normalized substring matching — strict
  by design (CP25) to force accurate citation; CP31 may add fuzzy matching +
  uncertainty escalation rather than rejecting.
- `source_text` is nullable; a candidate whose window has no text (empty/OCR
  page) fails `validate_source()` → not persistable, reviewable. Intentional.
- The candidate `raw_source` is model-claimed; the trusted `source_text` is
  service-set from `DocumentPage.cleaned_text`, so model claims are always
  checked against authoritative parsed text.
