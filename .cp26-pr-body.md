# CP26: LLM extraction adapter, prompt versions, and run metadata

## Why
Model calls are the next risk in the Phase 1 extraction pipeline: they must be
provider-agnostic (so swapping providers never rewrites document services),
deterministic-testable (no network in CI), and fully auditable (every call
traceable to the exact prompt/schema version, model, and EXTRACT-stage
processing run). CP25 bounded *model output* with the `RequirementCandidate`
schema but left the invocation seam unimplemented; this PR adds that seam and
wires it into the worker/service.

## What changed
- **Adapter port** (`extraction/adapter.py`): `LlmAdapter` ABC + frozen
  `LlmCallConfig`/`LlmCallResult`/`ExtractResult` dataclasses and a typed
  `LlmCallError`. Untrusted document text is accepted only as the `user_text`
  argument of `LlmAdapter.extract`; static application system instructions are
  passed separately (`system_prompt`), so document text can never override
  application/system instructions (CP26 guardrail + AGENTS.md "uploads are
  untrusted"). **Note:** `adapter.py` was authored in the CP25 trace but left
  untracked on `main`; this PR commits it as the CP26 adapter port.
- **`FakeLlmAdapter`** (`extraction/fake.py`): deterministic, no-network
  provider that serves pre-canned `ExtractionResponse` objects and records an
  audited `LlmCallResult` per call. Solely used by tests.
- **`OpenAiLlmAdapter`** (`extraction/openai_adapter.py`): production default
  (`gpt-4o` per `review.md`), structured output parsed directly into
  `ExtractionResponse`. The `openai` package is **imported lazily** (inside
  `_client()`) so `create_worker` / tests never require it; a real call needs
  `OPENAI_API_KEY` + the package at call time. The live-call test is opt-in
  only (`CP26_OPENAI_REAL_CALL=1`) so CI never incurs cost.
- **Prompt versioning** (`extraction/prompts.py`, already on `main`):
  `PROMPT_VERSION="1.0.0"`, `SCHEMA_VERSION="1.0.0"`,
  `EXTRACTION_SYSTEM_PROMPT` (fabrication guardrails: "verbatim",
  "fabricate"), and `ExtractionResponse` bounded schema. `extraction/__init__.py`
  now re-exports the port/providers/prompts.
- **Audit table** (`extraction_runs`, migration `0009_extraction_runs.py`):
  one row per LLM call anchored to `processing_runs.id`; records provider,
  model, prompt+schema version, `call_site`, latency, provider-reported tokens,
  finish reason, status, and best-effort cost. `NULL` = unknown (never a
  fabricated 0, per the LLM cost-logging SOP).
- **`ExtractionRun`/`ExtractionRunStatus`** models (`db/models.py`).
- **`DocumentService.log_llm_call(processing_run_id, call)`** — persists the
  audit record (flush, no source mutation). Anchoring on `processing_run_id`
  ties every call to a version + EXTRACT stage.
- **`create_worker`** injects a default `OpenAiLlmAdapter`; `JobProcessor`
  accepts an injectable `llm`. The EXTRACT stage remains a no-op (CP28 calls
  the adapter).
- **Config** (`config.py`): `openai_api_key`, `openai_base_url`,
  `openai_model="gpt-4o"`.
- **Tests** (`tests/test_extraction_pipeline.py`, 11 cases: 10 pass, 1 opt-in
  skip) + `tests/test_migration.py` updated (`head = 0009_extraction_runs`).

## Scope
Included: CP26 only (adapter seam + providers + prompt versions + run metadata
table + `log_llm_call` + worker/processor injection). Excluded: actual
requirement candidate extraction (CP28), chunking/hierarchy (CP27),
reconciliation (CP29), source anchoring/persistence (CP30) — all wired into the
EXTRACT stage later.

## Provenance / evidence impact
- Audit table records provider/model/prompt+schema version + run id per call —
  operators can explain exactly which extraction configuration produced which
  candidates (CP25/CP26 boundary: the model proposes, the service attests).
- No document bodies, citations, or compliance verdicts are stored in
  `extraction_runs`; it holds only LLM-call telemetry (Phase 1, no
  vendor-compliance status — per AGENTS.md Phase 1 domain states).
- Token counts / cost are nullable, never fabricated (cost-logging SOP).

## Risks / limitations
- `openai` is **not** a declared dependency (lazy import); production workers
  must install it + set `OPENAI_API_KEY`. This is intentional to keep CI
  network-/dependency-free; CP28 will depend on this for the real EXTRACT path.
- `OpenAiLlmAdapter` retry logic covers transient transport/timeout/parse
  failures; non-retryable provider errors surface as `LlmCallError` after the
  bounded retry budget (one audit row per logical call).
- The EXTRACT stage in `processor.py` is unchanged (no-op); extraction
  invocation lands in CP28.
- No migration for the `meta` JSON widening (CP24) — correct, none needed.
